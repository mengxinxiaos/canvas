# Canvas 按供应商、模型配置计价更新

适用于已经安装原 API 费用管理功能及计价快照版本的项目。本包基于此前交付的费用代码制作，不是整个仓库，也不是首次安装完整包。

## 完成的行为

- 后端 JSON 可为不同供应商、模型配置图片按张/Token，视频按秒/Token，或读取供应商返回金额。
- 具体模型规则优先于供应商默认规则；同一调用只按选定的金额来源结算，不自动换算法补金额。
- 张数、秒数优先使用实际输出，缺失时使用请求参数；零值有效，无效实际值不会被请求值掩盖。Token 使用实际返回用量。
- 本地单价仅在上游生成成功后结算，轮询、重复通知不重复计费；配置和价格保存为调用快照。
- zhenzhen 的 ×1.35、火山/poxian 的 Seedance 2.0 Token 单价保留。MiniMax、Aliyun 继续为空。
- 管理员明细显示按张、秒、Token 的公式及用量来源；四个统计卡片与按用户/模型的分组展示继续移除。

## 覆盖更新

1. 保存本地改动，尤其是自定义 pricing_rules.json。本包内配置保留此前确认的默认价格；自行改过的规则请合并。
2. 将包内 backend、frontend 目录中的文件覆盖到项目相同位置，不要用它们替换整个目录。
3. 按原部署方式重启后端。
4. 正式前端在 frontend 执行 npm run build，然后更新实际部署的 dist；开发模式刷新页面。

本次不新增依赖、不新增数据库字段和迁移，不需要 npm install，也不需要为本次扩展执行 alembic upgrade。前提是此前的 provider_cost、billing_model、pricing_snapshot 等字段已经存在。

后端必须已经注册 /api/admin/api-calls 和 /api/admin/api-calls/summary；本包没有重写 router.py。若这两个接口仍然 404，需要先完成基础费用功能的路由部署并重启正确的后端进程。

## 设置模型价格

编辑 backend/app/core/pricing_rules.json。文件末尾有五个未启用模板：按张图片、按秒视频、按 Token 图片、按 Token 视频、读取供应商费用。

模板不会自动产生价格。填写真实供应商、模型、已确认单价/系数后，再改 enabled 为 true。模型专属按张规则可以覆盖 zhenzhen 的通用返回金额规则，不需要删除所有供应商默认规则。

完整字段、条件价格、匹配优先级、实际用量来源和使用示例见 backend/PRICING_RULES.md。

配置变化只作用于新调用，不自动重算旧记录或已经开始的任务。修改代码需重启后端；部署后单独改 JSON 会由后续新调用读取。

## 可选补丁方式

canvas-model-pricing-v3.patch 与上述覆盖文件是同一份实现，二选一。补丁基于此前的 pricing-v2 及最新移除统计卡片的面板版本；工作区有自行修改时先 git apply --check，不通过不要强制应用，可按文件对比合并。
