# Generation Panel 改动与检查记录

基线：`mengxinxiaos/canvas`，`d166c804eaa0ca764d0ab2ad562def692a3fdd16`。分支：`fix/generation-panel-scalability`。

## 交互变化

- 图片、视频、音频分为三个区域，保留各类型自己的编号。
- 资产卡片按可用宽度换行。区域随内容增长，达到视口相关高度后纵向滚动；所有资产保留，不通过裁切数组解决显示问题。
- Seedance 2.5 显示合计计数与 50 项上限，超过上限可继续查看和移除，但不能提交。视频卡片不批量请求视频，悬停时仅加载一个预览。
- 同类型拖拽排序；成功放置才保存，取消拖拽不改变顺序。支持 Alt＋方向键排序。
- 时长使用配置驱动的滑条，“自动”独立选择。当前 2.5 的手动范围为 4–30 秒；切换其他模型时按该模型允许值校正。滑条也能处理非连续时长列表。
- 普通面板始终位于生成节点下方 16px，不自动翻到节点上方；窄屏缩小宽度，内容内部滚动。右上角提供全屏与退出全屏；全屏使用整个应用视口，桌面分栏、窄屏上下布局。参数浮层继续避开视口边缘。
- 全屏复用同一面板和编辑器，不重新挂载。提示词、引用顺序、参数与编辑器历史保留；Esc 优先关闭参数浮层，再退出全屏。退出后回到节点下方；背景键盘操作与页面滚动会恢复。

## 发现并修复的隐藏问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| ZhenZhen 后端用 `[:9]` / `[:3]` 裁切媒体 | UI 显示已引用，实际部分未发送，提示词编号可能失效 | 2.5 按合计 50 校验并完整传输；其他型号保留原有每类上限，超限明确报错 |
| 新节点默认 `first_last`，当前所有视频模型只声明 `multi_ref` | 模型列表为空，可提交不支持的模式 | 根据模型能力选择有效模式；不支持的模式按钮禁用 |
| 旧节点或切换模型保留非法时长、清晰度、比例 | 显示与请求不符合模型配置 | 初始化、交互和外部参数更新均归一化 |
| 参数保存与提示词/引用保存各自覆盖整份 generation | 新输入、排序或参数可能被旧快照覆盖 | 面板统一写入局部 patch；参数写入移出 React state updater |
| 外部断线不重映射提示词；关闭期间断线后重开也丢旧编号关系 | `@图N` 指向另一项或失效 | 使用资产 ID 和保存的输入快照映射编号；外部文本与顺序整体接收 |
| 删除资产保留永久本地 tombstone | 同一资产重新连接后仍不显示 | 以实际连线和保存顺序计算列表，取消永久屏蔽状态 |
| 多个失效 mention 使用旧文档坐标删除 | 误删邻近文字或事务异常 | 通过 ProseMirror transaction mapping 转换位置 |
| 编辑器异步回写、过期同步和非订阅占位显示 | 快速 Enter 提交旧文本；旧内容覆盖新内容；占位文字叠加 | 同步更新 prompt ref，取消过期同步，订阅编辑器空状态 |
| 外部/强制编辑器重绘进入撤销历史 | 排序后撤销可能恢复旧显示编号 | 同步事务不进入本地撤销历史 |
| 提交服务将 finalPrompt 写回可编辑 prompt | 生成后丢失 @，再次生成重复扩展预设 | 分离 rawPrompt、可编辑 prompt 与 finalPrompt |
| 宫格模板直接 push 到传入 inputs | 原引用被污染，重复生成累积模板 | 复制引用，仅在请求副本追加图片模板；视频不继承模板 |
| 显式空 inputs 被当成缺省 | 删除的资产经连线回退重新加入 | 只有未提供 inputs 才回退，[] 表示明确无引用 |
| 回退只识别图片；同一节点快速重复发送 | 视频/音频丢失，重复创建任务 | 回退统一媒体类型和保存顺序；增加项目＋节点级提交锁 |
| 空 src 资产显示编号但提交被过滤 | 显示编号与请求编号不一致 | 未完成上传/生成时阻止提交并提示；图片模型媒体类型、音频缺少画面参考也提前提示 |
| 依赖锁文件与声明不一致 | 干净环境 `npm ci` 失败 | 更新锁文件并验证干净安装 |

## 代码边界

- `src/utils/referenceMedia.js`：媒体类型、编号、顺序、序列化、提示词映射与引用校验的纯函数。
- `PanelFrame.jsx`：只负责定位、全屏展示、焦点与背景交互隔离；常规/全屏始终使用同一个 Portal 容器，避免切换重挂载。
- `GenerationPanel.jsx`：协调 prompt、引用和参数，用 patch 保存，不复制整份历史 generation。
- `useGenerationParams`：模型配置约束与参数状态；外部参数变化与 prompt/引用写入分开处理。
- `PictureTags`：分区展示和拖拽预览；不负责保存提示词或网络提交。
- `MentionTextarea` / `mentionDocument`：编辑器同步与 ID 关联，不承担模型约束。
- `generationSubmission`：请求构造、副作用与同步提交锁，和 React、API 导入分离，方便测试。

- `npm test`：33 项通过，覆盖编号/删除/重连、50 项、参数归一化、事务映射、请求输入副本、重复提交锁与浮层定位。
- `npm run test:browser`：15 项 Chromium 浏览器测试通过，覆盖 50 个混合资产、360px 窄窗口、30s/自动、模型切换、打开与关闭期间断线、键盘排序/撤销、实际拖放/取消、外部文本与顺序同时修改、最新输入提交、加载态阻止 Enter、超限与未就绪引用、外部参数更新及占位显示；新增节点下方锚定与画布偏移、全屏保留同一编辑器与草稿、Esc 顺序/焦点恢复、移动端全屏与窗口缩放检查；同时检查页面运行时异常。
- 修改文件的 ESLint 与 `git diff --check`：通过。
- `npm run build`：通过。现有主包体积警告仍存在，本轮未扩展到全站分包。
- `python -m pytest backend/tests/test_zhenzhen_reference_limits.py backend/tests/test_video_pricing_context.py -q`：22 项通过。
- 全量后端测试存在 4 项旧计价测试失败；在干净基线复现同样失败（`backend/tests/test_pricing.py` 的原有期望与当前计价规则不一致）。本轮没有修改计价规则。

50 项能力按本次提供的 Seedance 2.5 需求实现；后端用 HTTP mock 检查实际组装的内容完整性，未调用付费生成接口。供应商额外的文件大小、单项媒体时长等约束不在本轮验证范围内。
